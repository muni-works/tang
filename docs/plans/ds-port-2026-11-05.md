# DeepSeek-V4.1-Flash: porting the coder-next speed wins (2026-11-05)

Branch `frog/ds-tcx` (from `frog/integrate-2026-11-03` @ d6a30135, which holds 99f8c6f9,
406c4a91 and serve3 21e5a49f; `frog/integrate-launch-fixes` merged, so the 35066e91 WIP is
reverted). Mac-only phase: everything compiles and the CPU tests pass. Nothing has run on a
GPU yet. GPU plan: `artifacts/ds-tcx/README.md`.

## Where DeepSeek stands

- Last measured: **193 tok/s greedy** (200 tokens, DSpark spec, 8x H100 EP, wave 8e
  70928d3b), sampled T=0.6 150-190 tok/s, prefill ~460 tok/s (`crates/tang-llm/docs/deepseek-v41-plan.md`).
- Routed experts: 40 layers x 384 experts x 3 matrices, **fp4 e2m1 with e8m0 scales per
  32 columns** (fmt 3), about 272 GB. The shared expert is fp8 e4m3 (fmt 2). Activations
  are quantized to fp8 per 32-group with pow2 scales (`ds_ks_quant`). **None of it is GGUF**:
  there are no Q4_K superblocks and no mins.
- The decode MoE already runs on f16 tensor cores: `lin_mma` / `ds_moe_ks_*` does m16n8k16
  with f32 accumulate, decodes fp4 and fp8 to f16 exactly with integer ops, uses 8-byte
  activation loads and per-32 scales, and has the shared expert folded in as one more slot
  (`ds_moe_ks_*_s*`) plus a persistent form (`ds_moe_kp_*`). Prefill uses the 8-row tiled
  `ds_moe_ks_t{gu,down}`. So DeepSeek starts much closer to TCX than coder did.

### Batching, fit, EP

- **Batching:** none. `deepseek/serve.rs` serves one sequence at a time, prefills in
  `DS_PREFILL_CHUNK` = 1024 chunks, and has no prefix reuse. Speculation is the only
  multi-row path (verify windows t <= 8). The serve3 batch layer has nothing to land on
  until a multi-sequence scheduler exists.
- **Fit:** the experts alone are 272 GB, so no single stocked GPU holds them (H200 141 GB,
  RTX PRO 6000 96 GB, H100 80 GB). One GPU only works through the expert LRU
  (`DS_EXPERT_SLOTS`), at about 1 tok/s. The tiny fixture (`DS41_TINY`) fits anywhere and
  is what the kernel gates run on.
- **EP** (`deepseek/ep.rs`, `docs/deepseek-ep.md`): one thread and one `GpuModel` per GPU in
  one process. Expert `e` lives on rank `e % N`, and everything else is replicated. Every
  rank routes the same tokens, runs its own experts into a zeroed `y [t][d]`, and then
  `moe_reduce` all-reduces `y` (NCCL, or the deterministic Host backend in tests), and every
  rank adds the shared expert. Ranks 8 x H100 = 34 GB of experts each (the measured box);
  4 x H200 = 68 GB each also fits. World 1 is bit-exact (`ep_world1_is_exact`); larger
  worlds are judged on KL. Run the tests with `--test-threads=1`.

| `cx_sgemm_wide2` router | **adapt (small)** | DeepSeek's router gate is bf16 `ds_gemv_bf16_r1` (decode) / `ds_linear` (prefill). It needs a bf16 port of wide2, because the coder version reads f32/q8 segments | prefill only, router ~1-2% |

The GLM-5.3 port (`frog/glm5-tcx`) runs on GGUF Q4_K experts, like coder. DeepSeek's fp4
kernel shares no code with `cx_moe_*_q`, so factoring shared kernels is **not cheap**: the
weight formats differ at the fragment level. The shared piece is the idea (B-fragment-order
global reads, no staging) plus the gate harness, not a function.

## Order of work

1. **GPU gate for what is wired** (scripts in `artifacts/ds-tcx/`): run
   `gpu_tiny_moe_tcx_matches_ks` (bitwise) and the existing tiny suite with
   `DS_MOE_TCX=1`, then microbench gu/down against ks at real shapes (`mega_moe_slots` with
   `DS_MOE_TCX=0/1`).
2. If TCX wins: let the shared expert ride TCX too (an fp8 `moe_tcx_body<FMT=2>` variant, so
   the folded slot comes back), then make TCX the default.
3. 8-byte loads through the upload repack (phase 2), and the IMAD epilogue A/B.
4. Wide prefill: cp.async token tiles plus a z=1 grid in `ds_moe_ks_t*`, and a bf16 wide2
   router.
5. Batching in `deepseek/serve.rs` (multi-sequence decode). Only then do the serve3 layer
   pieces apply.

## Wired on this branch

- `DS_MOE_TCX=1` (default off) switches the t <= 8 grouped MoE gu/down for fp4 experts
  from `ds_moe_ks_*_f3` to `ds_moe_tcx_*_f3`. `moe_sh_ok` turns false, so the shared expert
  runs as its own MLP. `Kernels::moe_tcx_on` is a `Cell`, so tests can flip it.
- CPU tests (`cargo test -p tang-llm deepseek::tcx`): the f4h and f8h decodes are exact over
  every code, the A and B fragment columns agree and cover each group once, `byte_perm`
  matches CUDA, and the group-ordered, K-sliced dot matches the dense dequantized dot for
  S in 1, 2, 4, 8.
- The kernel source has **not** been through NVRTC (there is no CUDA on the Mac). The first
  GPU step is compiling it.
- Not wired: wide router, staged prefill. They are prefill-only, and DeepSeek's tiled path
  differs enough that they are not cheap here.
