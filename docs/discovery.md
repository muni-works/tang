# Discovery: online, scan and chunked lifts

`tang-compile/src/tensor_discover.rs` searches for single-pass
associative forms of multi-pass reductions and sequential recurrences;
`tensor_discover_catalog.rs` runs it over 60 ops (31 online, 29 scan;
`cargo test -p tang-compile --lib discover`). Everything below is
regenerated by `TANG_DISCOVERY_MD=out.md cargo test … catalog_meets`.

## The idea

**Online lift theorem (as implemented).** A two-pass reduction
`y = Σᵢ g(xᵢ, ρ(R₁(x)))` is one monoid whenever `{g(·, a)}` lives in a
finite-dimensional space closed under change of reference: with
`b = φ(a)` (`φ` = id or ln) and a basis `D` (`D₀ = g`) satisfying
`∂_{bᵢ}D = AᵢD` with constant `Aᵢ`, `D(x, b') = exp(Σ δᵢAᵢ)·D(x, b)`.
State = `(R₁ state, Σ D)`; combine moves each side's sums to the merged
reference. Finite translation-invariant spaces are exactly exponential
polynomials, so the family searched is well defined. Online softmax is
the case `D = e^{s−m}`, `A = −1`; Welford/Chan is `D = ((x−μ)ʲ)`, `A`
nilpotent (binomial shift). The engine emits `exp(ΣδA)` in closed form
from the joint spectral decomposition (projectors × finite nilpotent
series), so Jordan blocks (entropy) and mixed spectra (cross-entropy,
KL) come out exactly.

**How it is checked.** Candidate relations come from `tang-expr`
derivatives plus a least-squares fit at 64 sampled points. Only
polynomial relations simplify to a literal 0 under `tang-expr`'s
simplifier (it does not collect `exp2` terms), so most exp relations are
marked `numeric`. Every emitted monoid is then fuzzed against the
two-pass definition on random combine trees with identities mixed in
(backward-error scale, threshold 1e-8; observed ≤ 5e-14), and 12 of them
are also run through the `TensorGraph` interpreter
(`online_lift_matches_two_pass_in_the_interpreter`). The fuzz is the real
verifier: kinks (|x−μ|, ReLU thresholds, rounding) pass the derivative
closure almost everywhere and are **rejected** by the fuzz.

**Scan lifts.** Families: affine (Jacobian independent of `h`, checked
structurally via `deps()` on the symbolic derivative), affine after
`exp`/`ln`/`1/h`, max-plus, Möbius (Schwarzian = 0), affine in ≤3
observables (library: `hᵢ`, `hᵢ²`, `1/hᵢ`, `exp`, `ln`, `h₀h₁`, ratios,
d ≤ 2). Failures record a witness per family.

**Chunked lifts.** Matrix-state affine scans are classified by `A`
(identity / scalar / diagonal / α(I − βkkᵀ) / general) and turned into
the chunked matmul forms (linear attention, SSD, GLA, WY/UT delta rule),
then checked against the sequential scan (err ≤ 2e-13). The scalar-decay
classes are exactly tang's `DeltaForm`, which the CUDA chunked schedule
already recognizes.

**Negative results** (no lift in the searched family, with evidence):
tanh RNN, GRU, LSTM, logistic map, LIF with reset (Jacobian varies with
`h` in every coordinate; Schwarzian ≠ 0); standardized-logit attention
`softmax((s−μ)/σ)` (σ scales the exponent; `{e^{ts}}ₜ` is
infinite-dimensional — the closure fails in all 4 coordinate choices
and the fuzz rejects the partial fit); MAD about the mean, max-relative
ReLU attention, int4 absmax quantize (kinks/rounding: rejected by fuzz);
`exp(cos(s−a))` weights (closes, dim 2, but rotation spectrum ±i — not
emitted, a gap in the emitter, not a theorem); Welford as a 3-state scan
(outside the d ≤ 2 observable library). The diag-gated delta rule
(KDA-like) is found affine but `A` is classified General, so the
chunked lift does not handle it (Kimi's KDA paper has a chunked form:
a known gap).

Not attempted: top-p and entmax/sparsemax normalization need sorted
order statistics / a root solve for the threshold — `R₁` is not a
finite monoid, so they are outside the problem statement rather than
"not found". MoE renormalization: the top-k monoid state already holds
the answer (the catalog's second-pass formulation is correctly rejected).

## Benchmark: one-pass softmax-weighted variance

`Var_p[v]`, `p = softmax(s)` per row, inputs `s, v [rows, n]` f32. Both
graphs come from `online_graphs` (two-pass = online-softmax pass for
`(m, Z, Σpv)`, then `Σ p(v−μ)²`; one-pass = the discovered width-6
monoid), both `schedule_auto`, WGSL on Metal
(`cargo run --release -p tang-bench --example discover_variance`):

| rows × n | two-pass | one-pass | speedup | max rel diff |
|---|---|---|---|---|
| 4096 × 4096 | 0.867 ms | 0.329 ms | 2.63× | 3.8e-7 |
| 1024 × 16384 | 0.630 ms | 0.328 ms | 1.92× | 4.6e-7 |
| 16384 × 1024 | 0.865 ms | 0.455 ms | 1.90× | 3.6e-6 |

(Apple M4 Max; M4 timings drift up to 2× run to run.) One-pass at
4096² moves 134 MB in 0.33 ms ≈ 400 GB/s, near the memory roof. On CPU
(`examples/discover_bench.rs` + `bench/discover/harness.c`, clang -O3)
the one-pass is **slower** (121 vs 70 ms at 4096²): there it is
compute-bound and the generic combine pays two `exp` per element. A
production kernel would fold elements in blocks and rescale once per
block, as FlashAttention does; the engine does not do that yet.

**Backward.** Given the saved forward state `(m, Z, μ, Var)` the
gradient is elementwise — `∂/∂vᵢ = 2pᵢ(vᵢ−μ)`,
`∂/∂sᵢ = pᵢ((vᵢ−μ)² − Var)` — so no reduction is needed (the
FlashAttention-backward pattern; checked by central differences in
`weighted_variance_backward_is_elementwise`). `tensor_grad` does not
differentiate `MonoidKind::Other` reductions, so this backward is not
yet derived automatically; the honest route is differentiating the
two-pass spec and lifting its reductions, which is future work.

No RunPod GPU was used.
